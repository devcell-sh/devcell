# Visual UX Audit — devcell.sh — 2026-10-14

Screenshots: homepage (desktop 1440, tablet 768, mobile 375), docs/quickstart (desktop 1440), 404 (desktop 1440).

## Critical (breaks usability)

| # | Breakpoint | Section | Issue | Fix |
|---|-----------|---------|-------|-----|
| C1 | Mobile (375) | Comparison table | Table overflows viewport horizontally: 5 columns of data cannot fit in 375px. Users must scroll sideways with no scroll indicator. Cell text likely truncates or wraps illegibly. | Convert to stacked cards or a scrollable container with visible overflow hint (gradient fade + swipe prompt). |
| C2 | Mobile (375) | Feature cards ("What you get") | 6 cards stacked vertically create an extremely long scroll. Each card has dense body text at small sizes. The icon indicators (I, O, M) are tiny and lack context. | Consider collapsible accordion on mobile, or reduce card body text to 1-2 lines with a "read more" expand. |
| C3 | Tablet (768) | Hero section | Terminal mock is pushed below the fold entirely. At tablet width the hero text area takes full width and the terminal starts below the CTA buttons, requiring scroll to see the product demo. | At 768px, consider keeping a narrower terminal inline beside the hero text (60/40 split) or placing it directly after the headline before body copy. |

## Major (hurts perception)

| # | Breakpoint | Section | Issue | Fix |
|---|-----------|---------|-------|-----|
| M1 | Desktop (1440) | "What you get" cards | The 6 feature cards use a 3x2 grid. The top row cards have inconsistent content length: "Container Sandbox" has ~5 lines, "Egress Lockdown" has ~4, "No Account, No Login" has ~6 lines including a code snippet. This creates uneven card heights. | Set a min-height on cards or use CSS `grid-template-rows: subgrid` so rows align. Alternatively, trim copy to equalize. |
| M2 | Desktop (1440) | "What you get" cards | Each card has a small single-character icon in a circle (I, O, M, etc.) that lacks semantic meaning. These look like placeholder icons rather than intentional design. A first-time visitor won't understand what "I" or "O" means. | Replace with recognizable icons (lock, shield, terminal, gear, etc.) or remove entirely: the bold card titles already communicate the topic. |
| M3 | All | Project/Cell/Host boundary table | The boundary table (Project / Cell / Host rows) uses small gray text on white. The inline green/yellow badges for `project`, `docker`, etc. are hard to read at body-text sizes. The table sits oddly between the feature cards and the "One CLI" section with no clear section heading. | Give it a proper section heading ("Security Boundary" or similar). Increase font size for the badges or use a styled table with borders. |
| M4 | Desktop (1440) | "One CLI. Three Environments." | The three OS cards (Linux, macOS, Windows) have inconsistent descriptions and CTA button widths. The Linux button says `devcell claude`, macOS says `devcell claude --os macos`, Windows says `devcell claude --os windows`. The longer text makes the macOS/Windows buttons wider, breaking visual symmetry. | Normalize button widths with a shared min-width, or move the OS flag into the card description and use a uniform CTA label. |
| M5 | Mobile (375) | "One CLI. Three Environments." | The three OS cards stack but the OS logos (penguin, apple, windows) are very small. The section heading "ONE CLI. THREE ENVIRONMENTS." is very large relative to the screen, taking up significant vertical space. | Reduce heading size on mobile. Consider a horizontal row of three icon+label items rather than full cards at this breakpoint. |
| M6 | Desktop (1440) | Comparison table ("How it compares") | "Daytona" column header is present but per LANDING.md, Daytona was archived Oct 2026. The table shows stale competitor data. (Visual issue: the column still renders and takes space.) | Remove Daytona column and replace with current competitors per LANDING.md. |
| M7 | Desktop (1440) | Comparison table | The "DevCell" column header uses a dark background pill/highlight, but the remaining column headers are plain text. This creates an unbalanced visual weight that reads as self-promotional rather than neutral comparison. | Use consistent header styling across all columns, or use a subtle highlight (border/underline) instead of a filled background. |
| M8 | All | Footer | Footer text "DevCell — Apache 2.0 License" on the left, links on the right. On the 404 page, the footer appears mid-page with large empty white space below it. This is because the page content is short and the footer isn't pushed to the bottom of the viewport. | Use a sticky footer pattern (min-height: 100vh on main + margin-top: auto on footer, or flexbox). |
| M9 | Desktop (1440) | Docs sidebar | The sidebar has 20+ items in a single scrolling list. "GETTING STARTED" has 1 item, "CONFIGURATION" has 2, then "GUIDES" has 15+. The guides list is not grouped or collapsible, making it hard to scan. | Group guides into sub-categories (Setup, Workflows, Advanced) or make the sidebar collapsible by section. |
| M10 | Desktop (1440) | Stacks section ("Focused Stacks") | The section body text mentions `devcell stacks` and `devcell-sh/home` in inline code, but the section lacks a visual element: no stack comparison table, no cards, no visual. It's just two paragraphs of text followed by "Compare the stacks →" link. Feels unfinished. | Add a mini grid of 3-4 hero stacks (base, go, electronics, security) with brief descriptions to give a visual anchor. |

## Minor (polish)

| # | Breakpoint | Section | Issue | Fix |
|---|-----------|---------|-------|-----|
| P1 | Desktop (1440) | Hero eyebrow | The "Open Source · Apache 2.0" text and the badges bar sit on different visual baselines. The shields.io badges (version v0.9.0, last commit today) are vertically misaligned with the surrounding text by ~2px. | Align badges vertically with `vertical-align: middle` and adjust line-height. |
| P2 | Desktop (1440) | Hero | The Anthropic quote blockquote has a light gray background (#f5f5f5 approx) with a left border. The quote attribution "ANTHROPIC, CLAUDE CODE DOCUMENTATION" is in all-caps small text. The caps styling feels slightly aggressive for a quote attribution. | Use title case or small-caps for the attribution line. |
| P3 | Desktop (1440) | Hero "Works with" strip | The four agent logos (Claude Code, Codex, Gemini CLI, OpenCode) are rendered as small icons followed by text labels. The OpenCode icon (">_" terminal prompt glyph) is visually distinct from the other three which are branded logos. It looks like a placeholder. | Either source an OpenCode brand mark or remove the icon and keep text-only for all four for consistency. |
| P4 | Tablet (768) | Hero eyebrow | At 768px, the eyebrow line wraps: "Open Source · Apache 2.0 · ★ GitHub · Releases · [badges]" becomes a single long line that barely fits. The badges are right-aligned while the text is left-aligned, creating an awkward float. | On tablet, stack the badges onto a second line below the text, or hide the text and keep only badges. |
| P5 | Mobile (375) | Hero eyebrow | The eyebrow wraps to 3 lines. "Open Source · Apache 2.0 ·" on line 1, "★ GitHub · Releases · [version badge] ·" on line 2, "[last commit badge]" on line 3. The wrapping creates an orphaned badge on line 3. | Simplify: show only 1-2 badges on mobile, or collapse into a single "v0.9.0 · Apache 2.0" line. |
| P6 | Desktop (1440) | Quickstart section | The quickstart uses a numbered list (1, 2) with large green circle indicators. The green circles use the accent color (#C8FF00) which is slightly hard to read as dark text on bright green. The "1" and "2" inside the circles are small. | Ensure contrast ratio meets WCAG AA (4.5:1 for text). Consider dark green or use the circle as decoration with the number outside. |
| P7 | Desktop (1440) | Quickstart terminal mock | The right-side terminal in the quickstart section shows `brew install devcell-sh/tap/devcell` on a dark background. This duplicates the install command from step 1 on the left. The terminal mock feels redundant: the user already saw the hero terminal mock above. | Remove the quickstart terminal or differentiate it (show the first-run output instead of the install command). |
| P8 | All | FAQ section | FAQ uses disclosure triangles (`<details>`) with no visual styling beyond the browser default. The questions are in regular body font with no visual differentiation. The section feels unstyled compared to the rest of the page. | Add hover states, a border or card treatment per FAQ item, and slightly bolder question text. |
| P9 | Desktop (1440) | 404 page | The 404 page has a large amount of whitespace below the footer. The footer renders at roughly the 40% mark of the viewport, with ~60% empty space below. Likely the same sticky-footer issue as M8 but more pronounced here. | Same fix as M8: sticky footer. |
| P10 | Desktop (1440) | Docs page | The docs page uses a dark theme (dark sidebar, dark code blocks, dark nav) while the homepage is white/light. The theme switch when navigating from homepage to docs is jarring. | Consider making the docs theme lighter to match the homepage, or add a subtle transition. Alternatively, make the homepage nav dark to bridge the two. |
| P11 | Mobile (375) | Navigation | The mobile nav collapses to a hamburger menu (≡). This is correct behavior but the hamburger icon is very small and positioned at the far right edge with tight padding. | Increase hamburger hit target to at least 44x44px (iOS HIG minimum). Add slight padding. |
| P12 | Desktop (1440) | Comparison table | The "not yet" cells for DevCell (Credential Brokering, Snapshot/Restore) use plain text. These honest gaps don't visually differentiate from "no" cells in other columns. A reader scanning quickly might conflate "not yet" (planned) with "no" (not planned). | Style "not yet" differently: italic, a distinct color, or add a small "planned" indicator. |
| P13 | Desktop (1440) | Hero terminal mock | The terminal title bar shows three dots (red, yellow, green) in the macOS window chrome style. The green dot is noticeably brighter than standard macOS green. Minor but noticeable to the target persona (macOS developers). | Match the standard macOS traffic light colors more closely. |
| P14 | Mobile (375) | Full page length | The full mobile page is extremely long (~7700px at 375px width). A user needs to scroll through ~20 screen-heights of content. There is no back-to-top button or sticky nav that would help orient. | Add a back-to-top FAB (floating action button) that appears after scrolling past the fold, or make the nav sticky on mobile. |
